# 任务需求：三炮十五兵 完备残局库 (Endgame Tablebase) 建设

> **目标**：解决在中低子力残局下（如 `5/2s2/1s1s1/1c1c1/5 c` 仅含 3 兵 2 炮），即使高达 20 层的 Alpha-Beta 搜索也因评估函数缺乏有效梯度而导致“无意义徘徊”的致命 BUG。采用逆向分析 (Retrograde Analysis) 构建精准的小规模残局宇宙，引擎挂载后实现查表即绝杀。

## 1. 第一性原理与痛点剖析

- **当前缺陷**：`evaluate_board` 依赖人工手搓的子力、位置、控制区权重。在棋盘广阔、剩余子力极少的残局中，这几个维度的得分往往形成“平原（Plateau）”——从当前节点看几层外的状态，分数完全相同。Alpha-Beta 搜索如果看不到终局的明确反馈（如吃子），就会茫然地在原地来回走动，消耗了 20 层深度却无法推进行棋进度。
- **降维打击**：5×5 棋盘的格子极少（总共 25 格）。对于少量棋子（如 5 子残局），其所有可能的物理摆放组合仅在几百万量级（例如 3兵2炮 的合法放法只有约 $C_{25}^3 \times C_{22}^2 = 531,300$ 种）。利用计算机的内存足以将其穷举并推算至最终结果。

## 2. 核心架构：逆向推演算法 (Retrograde Analysis)

相比于正向搜索可能产生的无限回环，逆向分析从已确定的“终点”往回走：

1. **铺设全集状态**：枚举目标子力配置下的所有可能状态，建立状态全集。
2. **终局标记 (DTM = 0)**：将所有游戏规则上已结束的状态（兵数为 0 判炮胜）和（行棋方已无合法走法判另一方胜）作为深度 0 初始化。
3. **退步传播**：
   - 假设当前为状态 A（未决），其某一子状态 B 是“对方必败，步数为 $d$”。则 A 即被证明为“我方必胜”，步数 $DTM = d+1$。
   - 若 A 的**所有**子状态都是“对方必胜，步数分别为 $d_1, d_2...$”，则 A 为“我方必败”，且步数为抵抗最久的 $\max(d_i) + 1$。
4. **环与和棋收敛**：经过多轮传播直到全集无新的状态被更新。此时尚未能证明必胜也非必败的状态，在双方最优策略下即为理论上的**和棋**。

## 4. 技术突破总结

1. **对称性压缩算法 (Canonical Hash)**: 利用 5x5 棋盘的 8 种对称变换，将 2C2S 状态空间从 15 万压至 1.9 万，解决了内存溢出风险。
2. **库间跳转架构**: 建立了“捕获即跳转”的逻辑，使生成器无需处理兵数变化的复杂度，只需关注当前兵数下的博弈，通过查询子库实现 DTM 引导。
