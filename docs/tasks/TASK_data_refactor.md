# 任务需求：数据格式重构与残局支持 (FEN/JSONL)

> **目标**：**彻底废弃**当前基于冗余嵌套数组的旧版 JSON 棋谱格式。全面转为以 FEN 字符串为核心的存储体系，并采用 JSONL 格式导出大规模训练数据，确保格式统一且不可回退。

## 1. FEN (Forsyth-Edwards Notation) 规范定义

针对《三炮十五兵》5x5 棋盘定制的字符串表达格式：

- **棋盘布局**：从第 0 行到第 4 行，每行用 `/` 分隔。
- **棋子表示**：`s` 代表兵 (Soldier)，`c` 代表炮 (Cannon)。
- **空位表示**：使用数字 1-5 表示连续的空格。
- **当前行棋方**：空格后跟 `s` 或 `c`。
- **示例**：`sssss/sssss/sssss/5/1ccc1 c`（开局阵型，由炮方行棋）。

## 2. JSONL 训练集格式

为了方便流式读取和大规模训练，采用每行一个 JSON 对象的格式：

- **字段**：`{"fen": "...", "eval": <分值>, "result": <1.0/0.5/0.0>}`。
- **要求**：导出功能应能一次性将历史记录转化为多行 FEN 记录。

## 3. 功能需求项

1. **[核心层]**：在 `GameState` 类中增加 `to_fen()` 和 `from_fen(fen_str)` 方法。
2. **[IO层]**：增加 `export_as_jsonl(history, filepath)` 接口。
3. **[逻辑层]**：在 `GameModel` 中埋入钩子，当监听到 `winner != NO_WINNER` 或触发和棋时，自动将当前残局以 FEN 格式追加保存至 `data/game_history/auto_save/`。
4. **[UI 层 - 核心需求]**：开发高效的“残局编辑器” (`EditorDialog`)：
   - **交互逻辑**：
     - **循环切换**：鼠标左键点击棋盘格，按 `空 -> 兵 -> 炮 -> 空` 顺序循环切换棋子状态。
     - **走子方选择**：提供“兵方行棋”和“炮方行棋”的单选按钮，默认为炮方。
     - **一键清空**：支持快速清除所有棋子。
   - **实时 FEN 联动**：
     - 界面下方实时显示当前局面的 FEN 字符串，支持一键复制。
     - 底部提供 FEN 输入框，支持粘贴外部字符串立即同步渲染至棋盘。
   - **规则校验**：
     - 实时计数：显示当前棋盘上的兵与炮的数量。
     - 合法性警告：当炮 > 3 或 兵 > 15 时，状态栏显示红色警告文字。
   - **功能集成**：
     - “回到对弈”按钮：点击后将编辑器内的局面注入主游戏并立即开始。

## 4. 交付物

- **核心逻辑**：包含 `to_fen()` / `from_fen()` 的 `core/game_logic.pyx`。
- **IO 模块**：彻底移除旧 JSON 逻辑、支持 FEN/JSONL 的 `src/io/game_io.py`。
- **模型支持**：实现终局自动 FEN 存盘的 `src/model/game_model.py`。
- **独立组件**：包含网格交互与 FEN 联动的残局编辑器 `src/view/editor_dialog.py`。
- **预设库**：一组标准格式的经典残局 FEN 示例文件。
- FEN分数细致对比：再额外增加一个script的需求，要求可以对比两个FEN局面的评分，包括子项评分，总分等对比。方便用户先期尝试性手调，看看方案是否具备可行性。
