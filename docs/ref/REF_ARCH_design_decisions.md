# REF: 设计决策记录

本文档记录系统的核心设计选型及其技术考量，为后续架构演进提供决策对标。

---

## 1. 组件间通信机制

决策：采用回调函数作为主通信接口。
理由：
- 简洁性：适配项目规模，规避过度工程化产生的总线开销。
- 静态分析：明确类型定义，提升静态检查与代码导航准确度。
- 无依赖性：消除外部事件库依赖，保持核心逻辑纯净。

---

## 2. 状态对象不可变性

决策：GameState 棋盘布局采用元组结构存储。
理由：
- 哈希一致性：满足哈希算法对不可变数据作为键值的要求。
- 版本溯源：支持通过状态快照进行历史记录管理。
- 状态隔离：消除由于对象引用导致的跨分支数据污染。

---

## 3. 并行计算调度

决策：后台任务采用守护线程并行运行。
理由：
- 交互保障：确保界面主线程免受高负载搜索阻塞，维持实时响应能力。
- 中断回路：建立控制层与计算层的隔离链路，支持随时终止搜索。
- 资源回收：利用系统机制实现程序退出后的资源清理。

---

## 4. 复盘系统数据流

决策：路径逻辑位于模型层，渲染分发位于调度器。
理由：
- 数据一致性：技术溯源基准对历史分支拥有绝对控制权。
- 视图解耦：在不改动界面逻辑的前提下实现多种复盘导航策略。
