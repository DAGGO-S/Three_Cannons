# 三炮十五兵 AI 算法技术规格书 (Technical Specification)

本文档详述了当前系统的 AI 决策逻辑、搜索优化及架构设计，旨在提供系统化的技术参考。

## 1. 核心架构：Cython 高性能内核

系统采用 **Python 驱动 + Cython 内核** 的混合架构，核心搜索逻辑全部运行在 `nogil`（无全局解释器锁）环境下，以达成极致的内存访问速度和计算吞吐量。

- **`core.constants`**: 极简常量层，消除模块循环依赖，确保 C 级编译效率。
- **`core.engine`**: 递归搜索内核，实现 Alpha-Beta 剪枝，直接操作 C 结构体。
- **`core.search_manager`**: 搜索调度器，负责迭代加深、时间管理及进度反馈。
- **`core.search_infrastructure`**: 基础设施层，维护全局置换表 (TT) 和原子化节点计数。

---

## 2. 搜索策略：迭代加深与 PVS

### 2.1 迭代加深 (Iterative Deepening)
搜索并非一次性达到目标深度，而是从深度 1 开始逐层递增。
- **优点**：
    - **时间精度控制**：可在任何层级被安全中断，并返回上一层的最优解。
    - **哈希表复用**：深层搜索会从置换表中继承浅层搜索的最优走法，极大提升剪枝效率。

### 2.2 带 PVS 优化的 Alpha-Beta 剪枝
内核采用 **Principal Variation Search (PV 搜索)**，其逻辑基于“假设第一个搜索到的走法就是最好的”：
1. **全窗口搜索**：对第一个分支（由置换表建议的最优走法）进行全窗口 (Alpha, Beta) 搜索。
2. **零窗口探测 (Null-Window Search)**：对后续分支先进行精细的零窗口探测 `(alpha, alpha + 1)`。
3. **重搜索回退**：仅当零窗口探测失败（证明分支可能更好）时，才发起代价更高的全窗口重搜索。
- **效果**：NPS 虽略有降低（因逻辑分支变多），但每秒能搜索的有效深度（Depth）由于剪枝率提升显著增加。

## 3. 缓存机制：置换表 (Transposition Table)

采用 **Zobrist Hashing** 为每个棋盘位置生成唯一的 64 位指纹，映射至 400 万个条目的高速哈希表。

### 3.1 状态存储 (TT Entry)
每个条目存储：
- `hash_key`: 校验冲突。
- `depth`: 该分数的计算深度。
- `score`: 分数值（处理过准确分、上限分、下限分）。
- `flag`: 区分准确分 (EXACT)、下限 (LOWER) 或上限 (UPPER)。
- `best_move`: 该位置产生的历史最佳走法（用于走法启发）。

## 4. 评估逻辑：启发式打分 (Heuristic Evaluation)

系统评估逻辑完全基于 `core/evaluation_logic.pyx` 中的现有高性能实现，未作改动。其核心由以下维度构成：

### 4.1 动态兵力权值 (Material Evaluation)
不同于简单的权值累加，系统采用 **阶梯分值表** (`BASE_MATERIAL_SCORES`)：
- 根据当前存活士兵数量 (1-15) 映射不同分值。
- **炮方优势期**：兵力较多时得分极高（最高 +1600），反映炮方初期强大的压制力。
- **相持与劣势**：随着兵力减少，分值呈非线性下降，直至负值，反映残局阶段兵方合围的威胁。

### 4.2 空间位置与战术惩罚 (Position & Proximity)
- **士兵位置表** (`SOLDIER_POSITION_TABLE`)：5x5 矩阵精确定义了士兵在不同深度的战略压迫分，核心逻辑是奖励士兵向炮方阵地垂直推进。
- **贴炮惩罚** (`WEIGHT_SOLDIER_PROXIMITY`)：当士兵出现在炮的相邻格（上、下、左、右）时，给予固定负分惩罚。这模拟了炮被“粘住”后机动性丧失的风险。

### 4.3 核心：净控制区评估 (Net Control Area)
这是系统最先进的逻辑，完全基于 **位运算 (Bitmask)** 实现：
1. **禁区计算 (Forbidden Mask)**：计算所有炮的当前攻击路径和预瞄路径，生成兵方不可进入的“禁区”。
2. **安全区 BFS**：以所有安全士兵为起点，通过位运算进行快速 BFS 传播，找出兵方所有能连通且安全的活动空格。
3. **净控制率评分**：计算总共有多少格属于兵方的“安全活动区”，并通过 `WEIGHT_NET_MAP` 映射为最终分数。
- **意义**：该逻辑不看表面走法，而是看“势”。如果兵方虽然人多但被限制在极小的死角内，该指标将直接判定其为大劣。

## 7. 搜索稳健性：三复局倾向判定
为了防止 AI 在优势下陷入无效循环，`core/engine.pyx` 实现了基于兵数的“三重复局面”判定逻辑（$\le 8$ 兵炮胜，$\ge 10$ 兵卒胜，9 兵平局），迫使 AI 在优势下主动寻求破局。

## 8. 结论
目前的 AI 结合了 C 级位运算性能与定制的空间控制评估算法，并通过 NNUE v2 显著提升了中后局的判别精度。
