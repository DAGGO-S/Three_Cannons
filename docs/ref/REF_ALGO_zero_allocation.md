# REF: 引擎零分配重构与优化报告

本文档整合本项目从 11万 NPS 向近 60万 NPS 迈进的底层重构过程与性能剖析数据。

## 1. 重构背景与基线测算

在初始形态下，引擎受到垃圾回收机制与运行时对象分配的制约。
- 初始瓶颈：局面走子与走法生成涉及大量元组和列表的重复推导。
- 初始基线：标准开局 12 层深度的搜索速度为 110000 NPS。
- 核心目标：消除搜索热点路径中的动态内存分配，将引擎算力提升至指令吞吐极限。

## 2. 核心重构阶段记录

重构过程遵循基线测量、隔离验证与算力验收的闭环法则。

### 阶段 1：评估函数的纯 C 化与位域压缩
- 问题：旧版评估函数占用近半数计算时间，主要原因为生成嵌套数据及执行广度优先搜索时的堆分配。
- 实施：废弃嵌套元组，采用一维 C 数组呈现棋盘。将位置得分转化为位操作。
- 效果：NPS 提升至 379000。

### 阶段 2：走法生成机制的静态化
- 问题：生成走法列表产生海量碎片内存。
- 实施：剥离列表对象，改为传入预分配空间的掩码栈数组指针。
- 效果：走法生成耗时剧减八成，整体 NPS 达到 470000。

### 阶段 3：原位回溯与探索容器消解
- 实施：开发测试体系保护逻辑重构时的一致性。去除火炮禁区探测产生的动态集合与双端队列。引入原位操作机制替换状态复制。使用静态数组替代字典作为置换表。
- 效果：节点测算速度达到 524000 NPS。

### 阶段 4：解除搜索堆栈对象分配
- 问题：引擎在每层深度递归时构造多元组封包返回值。
- 实施：将搜索函数返回类型修改为单一浮点数。停止在搜索层内维护最佳路线表。在最外层提取哈希缓存复原走法路线。
- 效果：单线程测算极速达到 597996 NPS。

## 3. 结论

系统底层框架在摒弃垃圾回收开销及执行原生数据交互后，达成了约 5.4 倍的算力提升。后续优化重心应移交至启发式修剪与底层编译指令优化。
