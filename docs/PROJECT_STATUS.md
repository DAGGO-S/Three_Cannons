### 棋力突破路线与瓶颈分析 ⚠️

为了进一步提升 AI 的棋力，必须从以下几个维度的方案进行拆解和攻克：

#### 1. 算法架构选择设定

- **现状与评估**：目前使用 Alpha-Beta 剪枝 + PVS + LMR + 迭代加深的架构。
- **MCTS 考量**：此前已经论证过，对于“三炮十五兵”这种战术性极强、步法陷阱密集的非均匀分支游戏，依赖随机采样的 MCTS（蒙特卡洛树搜索）极大概率不如带有强剪枝与优质局部静态评估的 Alpha-Beta 树。因此核心算法路线是合理的，持续深挖 AB 树是正确的方向。

#### 2. 计算速度的绝对瓶颈 (NPS 攻坚)

- **现状与评估**：经历了彻底纯 C 化 `evaluate_board` 并解除堆栈对象分配，以及走法生成的 C 数组化改造后，NPS 已爆发至 ~470k。
- **目前的堵点**：最大开销转移到了 `c_move_piece` 内部的 `GameState.__new__`。
- **突破方案 [原位状态回溯 (Make/Unmake)]**：理论上可以通过前向/回溯原位操作彻底消灭这最后一层对象分配，从而冲击 1,000,000 NPS。
- **[当前结论: 已暂缓]**：由于该方案极其容易引入隐蔽的状态污染 BUG，风险太高，且目前的 470k NPS 能够满足现阶段业务测试的搜索深度需求，经过权衡已决定暂缓开发。

#### 3. 评估函数的盲区与天花板

- **现状与评估**：彻底纯 C 化与位域转换让静态评估的执行速度飙升到了极致。但代价是：纯手工拟合权重参数已经达到“天花板”效能。
- **面临的挑战**：为了测量绝对速度临时切断了 QS（静默搜索），导致 AI 的静态评估视野存在严重盲区（无法看透连环吃子战术漏洞）。
- **突破方案**：下一步不仅需要恢复 QS，还需要在基于位运算的极速 C 评估函数中融入更多的静态局部战术标定，以弥补不搜索时的盲区。

#### 4. 空步裁剪的永久禁用 ⛔

- **现状与评估**：考虑到该游戏存在大量的 Zugzwang (逼走劣局) 情况，而目前没有完善的理论支撑如何解构这些边界条件。
- **[当前结论: 永久禁用]**：在完全解决清楚 Zugzwang 问题之前，重新开启 Null Move Pruning 的动作都是错误的。空步裁剪已被列入黑名单。

#### 5. 绝对完美的残局/开局表 

- **现状与考量**：到了算力与手工评估函数的极限后，唯有依赖确切的数据表。
- **突破方案**：构建 残局表）能够让 AI 在游戏后期获得上帝视角（完美信息）。同时也可以引入开局表防止前期走出低级错误。
