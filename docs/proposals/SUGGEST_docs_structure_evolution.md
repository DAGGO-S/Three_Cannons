# SUGGEST: 文档体系重构与工作流效能进化提案

本提案旨在通过优化 `docs/` 文件夹划分与工作流匹配逻辑，提升知识库的检索效率、实验可溯源性及资产纯净度。

---

## 1. 目录架构重构方案

建议将目前的线性目录结构演进为具备核心、动态、观测维度的网格化结构。

### 1.1 新增：docs/specs/
职能：存储静态、稳定的数据协议与标准。
- `SPEC_FEN_FORMAT.md`：5x5 棋盘 FEN 扩展规范。
- `SPEC_DATA_PROTOCOL.md`：JSON 棋谱与自对弈数据存储格式。
理由：将协议校验与架构逻辑解耦。

### 1.2 新增：docs/experiments/
职能：存储具备科学规律的定量对比数据。
- `EXP_{DATE}_{ID}.md`：记录特定权重、搜索参数的对比测试结果。
理由：将实验分析与日志记录剥离，利于数据横向对比。

### 1.3 优化：docs/ref/
引入二级分类标签：
- `REF_ARCH_`：系统拓扑、分层职责、通信路由。
- `REF_ALGO_`：搜索剪枝、评估内核、训练算法。
- `REF_INTERFACE_`：接口签名、配置文件规范。

---

## 2. 工作流匹配优化

### 2.1 三段式减熵提炼标准
在任务完结并转化为参考资产时，强制执行信息浓缩清单：
1. **Fact**：最终验收数据。
2. **Logic**：物理重构路径。
3. **Constraint**：由次产生的新技术约束。

### 2.2 引入 REF_DEBT_
针对提案中未能实施但具备价值的方案，转化为技术债记录。
价值：作为负面清单或未来路线图，防止重复性无效探索。

---

## 3. 演进路径

1. **第一阶段**：重写文档工作流标准以注入上述规范。
2. **第二阶段**：执行目录迁移。
3. **第三阶段**：执行前缀规范化更名。

---
本提案遵循冷峻客观原则，旨在以最小的组织成本换取最高的信息确定性。
