# 底层数据结构 C 语言化降维重构任务 (Zero-Allocation Refactor)

此任务清单拆解自性能优化讨论，核心目标为：消除博弈树搜索热点路径中的动态内存分配，将引擎算力提升至受制于 CPU 指令吞吐而非内存位移的物理极限。

## 闭环验证要求

1. **性能基准闭环**：在重构前，必须运行现有的基准测试脚本 `scripts/bench_fixed_depth.py`（基于初始局面，固定深度 12 层），记录当前 `AIEngine` 的 NPS（每秒节点数）和总耗时。重构完成后，运行同一脚本，必须在客观数据上证明 NPS 获得数量级提升。
2. **逻辑一致性闭环**：在重构过程中，`GameState` 的任何修改，都必须通过 `tests/test_game_logic.py` 的全量测试。确保降维后的状态机行为与原生逻辑绝对一致。

## 具体执行微小任务 (Micro-Tasks)

### 阶段一：建立性能基准（Benchmark）
* 运行现有的性能评估标准脚本 `scripts/bench_fixed_depth.py`。
* 该脚本锁定初始局面为起点，并以 12 层搜索深度作为统一标准进行引擎摸底。
* 记录改版重构前的总耗时与节点展开数量作为性能基准参考线。

### 阶段二：重塑 GameState 为静态结构
* 修改 `game_logic.pyx`，彻底废弃用嵌套 `tuple` 表示的 `board`。
* 引入一维整数数组（长度 25）替代二维棋盘。
* 将坐标体系 `(r, c)` 重构为单一索引 `idx = r * 5 + c`，并提供宏或内联函数实现转换映射。

### 阶段三：走法表示的位压缩
* 将移动动作 `move` 从对象或多元组形式重构为一个 16 位无符号整数 (`uint16_t`)。
* 规定位域划分：
  - [0-4] bit: 起点索引 (0-24)
  - [5-9] bit: 终点索引 (0-24)
  - [10-13] bit: 捕获的棋子类型 (用于撤销移动时复原)
  - [14-15] bit: 特殊标识

### 阶段四：实现在位覆写的状态更迭 (make/unmake)
* 在 `GameState` (或对应的底阶 C 结构体) 中引入 `make_move(move)` 替代原先直接返回新实例的逻辑。`make_move` 执行位元交换与吃子移除。
* 编写配对的 `unmake_move(move)` 函数，用于在叶子节点求值完毕后，将棋盘数组严格归位至上一层状态。
* 在每一步 `make/unmake` 之中同步增减控制 `Zobrist` 哈希值，摒弃全量计算哈希。

### 阶段五：置换表的静态数组化
* 在 `ai.pyx` 内部废弃使用 Python `dict` 构建百万级 TT (Transposition Table)。
* 定义 `struct TTEntry`，预先在堆叠分配一个 2 的整次幂大小的定长数组 (如 `4194304`，避免取模除法，改用位与运算 `hash_key & 0x3FFFFF` 寻址)。
* 建立基于深度的覆盖替换策略结构。

### 阶段六：评估函数的轻量化切削（可选视算力溢出情况而定）
* 当算力由于前述步骤获得跃升时，深度搜索将自然规避许多战术盲区。
* 此时需审视 `evaluation_logic.pyx`，可考虑剥离耗时的 BFS 连通域计算逻辑，降配为纯位置分表格与子力基础分相加，验证是否在实战中更为精确。
