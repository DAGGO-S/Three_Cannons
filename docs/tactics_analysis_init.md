# AI 战术提升分析与构思

> **文档目的**：基于游戏原始物理规则与第一性原理，客观审视当前 AI 的战术盲区，批判性反思评估函数的局限，并构思下一阶段的进化路径。

## 1. 认知纠偏与现状诊断

通过对《三炮十五兵》核心规则的再次梳理，我们必须首先纠正先前战术构思中的致命认知错误：

1. **静默搜索在此不对称规则下的结构性缺陷。**
   之前的构思中将针对吃子的“静默搜索”作为普适策略。“三炮十五兵”规则中，一方只能吃子（炮），另一方只能合围（兵）。
   * **非平衡的搜索树与深度损耗**：单向吃子导致搜索树失衡。当到达叶子节点时，炮方存在吃子动作，静默搜索会继续展开；但轮到兵方时，由于无法吃子，系统将状态评估为“静息”而调用静态评估终止搜索。
   * **兵方的探索盲区**：这种不对称导致炮方评估出更多步的动态变化，而兵方对于回合后即将遭遇的限制状况缺乏探索。静默搜索为了炮方吃子消耗了算力（导致全局深度掉2层），却忽视了兵方的限制空间博弈，算力收益分配失调。
2. **约束条件：行棋规则无法跳过回合。**
   以此推论，“空步剪枝”在此项目中具有不合理性。本游戏中“逼走劣着”是常见的终结与战术形态。不管是兵被迫让出防守点，还是炮被迫走入死胡同，跳过回合的假设都违背了规则本身。空步剪枝目前处于禁用状态。
3. **评价体系的局限：高度依赖人工设定的魔法数值。**
   目前 AI 存在短板，核心问题并不在缺少战术逻辑，而在于现有的评价系统完全是由人工主观预设数值决定。由于舍弃静默搜索以期拿回2层深度，单纯依赖人工调整特定棋局模式不仅会导致框架冗长，且永远无法覆盖真实对局的博弈深度。

## 2. 基于第一性原理的系统重构

抛弃过多的人为主观经验设定，算法的博弈强度应源于数学严谨性与搜索树结构的客观统计。

### 路线 A：提升搜索树质量（内生战术，高收益，低风险）

与其教 AI 什么是“好形态”，不如让 AI 利用现有的极致算力更高效地去发现“好路径”。

1. **引入纯净启发式排序**：
   * **杀手走法启发**：在每一层记录引发剪枝的走法。下次遇到同层状态时优先尝试这个被验证过的“杀招”。
   * **历史表启发**：统计搜索树中各走法促成剪枝的历史命中率。
   * **收益**：此方法完全基于统计指标。不仅能极大提升剪枝效率，还能让 AI 自发形成连贯的战术组合。

### [高风险/非首选区] 路线 B：定制化扩展搜索或静态穷举分析

为了弥补静默搜索失效及全局深度下降问题，存在两种补偿深度的变通手段。但在评估投入产出后，已暂缓执行或列入非优选队列：

1. **定制化静默搜索**：放弃通用吃子触发，改由炮方过滤无效送吃、兵方通过“强制性空间压缩”（炮的合法步被减少）来触发叶子节点延伸。
   * *暂缓原因*：在系统底层实时界定“空间压缩”开销较大，大概率会超越直接增加1层全局深度的代价，拖累 NPS。
2. **依赖死路掩码预判的纯静态分析**：保持全深度搜索，并在纯 C 位域评估中增加相关的“死局预判”掩码结构，提前识别被困阵型。
   * *暂缓原因*：人工穷举并提现所有合围或半困阵型存在逻辑维护代价。只要特征库存在遗漏，AI 仍会受到水平线效应的影响，整体维护难度与效果不成正比。

### 路线 C：Texel 自动化调优体系

人工设定分数值存在局限性，普通线性回归也难以捕捉深层博弈树下特征之间的非线性组合效应。Texel 调优的核心逻辑是：在保持现有 C 语言位域框架执行效能不变的基础上，将评估权重交由基于海量自我对弈样本的数据学模型收敛得出。

此方案完全在线下进行，包含三个核心阶段：

1. **海量数据集生成**：利用当前 470k NPS 引擎进行千万次级别的自我对弈。随机抽取非激烈交锋的静息局面，记录并打上最终真实的胜负标签（兵胜1.0，炮胜0.0，和棋0.5）。最终产出包含数百万个 `[局面位域状态, 最终真实胜率]` 的庞大数据集。
2. **建立博弈树误差函数**：定义特定的 Sigmoid 误差函数，用来衡量“当前 C 位域算出的静态分数”与“最终对弈真实胜率”之间的偏差。目标是整体最小化这个偏差。
3. **局部梯度微调**：采用坐标下降等局部搜索算法，自动微调 C 代码里的具体特征权重（例如兵向前走一步加几分），若该方向使得整体数据集误差缩小，即接纳新权重。

#### Texel 调优的利弊评估

* **收益面**：
  - **零运行时开销**：由于最终产出的只是一组常量替换原有参数，所以能在不影响引擎基础算力速度（NPS）和内存操作的条件下接入系统。
  - **消除主观偏见**：模型通过统计下降寻找使得胜率预测误差最小的微观比例，免去人工校准几十甚至一百分之内的具体差异。
  - **算法域自洽**：得出的参数是引擎在原有 Alpha-Beta + PVS 机制搜索深度的背景下自身训练拟合的产物，更契合现有架构状态。
* **风险面**：
  - **庞大的工具链搭建跨度**：需额外开发多线程对弈生成器、持久化数据记录和批量微调模型，属于典型的基建与脱轨数据工程。
  - **依赖先验特征**：如果基础的 C 评估机制中不存在某些有效特征的记录与提取逻辑，调优系统也不会自动产生与其权重的映射。前期基建设定中的特征完整度依然不可或缺。
  - **搜索短视所致的过拟合**：用于生成数据的对弈如若执行深度过浅，AI 的残局败落会被错误地计入其静态权重的惩罚中，带骗训练的收敛结果。

## 3. 开发规划

既然定制化搜索与静态掩码列举机制需要较高的试错与运行成本，而权重自动调优亦需远期的脱轨支持。基于投入产出比考量，首要任务应当集中于 **路线 A：纯粹的算法级启发式排序（杀手走法与历史表启发）** 的改造。

**下属阶段目标总结：**

1. 修正对于不平衡规则中 QS 与 NMP 效果的错误预估，认同将它们暂时移出主要功能库。
2. 规避纯静态掩码枚举的非遍历陷阱。
3. 致力于利用高速纯 C 环境结合启发式排序机制来内生地提高引擎攻防推演能力。
