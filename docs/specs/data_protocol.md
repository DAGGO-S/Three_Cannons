# 数据协议规范

为了确保 NNUE 训练、数据重标以及自对弈系统之间的物理对齐，所有 `.jsonl` 数据文件必须遵循以下统一标准。

## 1. 核心字段定义

| 字段名    | 类型   | 说明                                         | 示例                        |
| :-------- | :----- | :------------------------------------------- | :-------------------------- |
| `fen`     | String | (必须) 局面 FEN 字符串                       | `"5/4s/1ss2/sscs1/cscs1 c"` |
| `eval`    | Float  | (必须) 局面评估分，±10000 表示绝杀           | `432.5` / `-10000.0`        |
| `outcome` | Float  | (必选) 最终胜负结果 (1.0=胜, 0.5=平, 0.0=负) | `1.0`                       |
| `depth`   | Int    | (可选) 产生该分数时的搜索深度                | `10`                        |
| `move`    | String | (可选) 该局面下的最佳走法                    | `"c3c4"`                    |

## 2. 格式约束

- **行式存储**：每个 JSON 对象必须单独占一行。
- **编码方式**：必须使用 `UTF-8` 编码。
- **数据单纯性**：禁止包含任何与评估/搜索无关的调试字符串或表情符号。

## 3. 分数视角规范

为了杜绝视角混淆带来的训练波动，项目中所有数据的 `eval` 和 `outcome` 必须统一使用 **炮 (Cannon) 视角**：

- **炮占优 / 炮胜利**：`eval > 0`，`outcome = 1.0`。
- **兵占优 / 兵胜利**：`eval < 0`，`outcome = 0.0`。
- **局面和棋**：`eval = 0`，`outcome = 0.5`。

## 4. 存储路径约定

- `data/selfplay/`：主训练原始数据。
- `data/game_history/auto_save/`：自对弈实时追踪数据。
- `data/endgame_mate_curated.jsonl`：物理精选的必杀局面集（由 `eval >= 9000` 的数据组成）。
