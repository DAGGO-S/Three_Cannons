# 贯彻 CLAUDE.md 核心纪律工作流

用于在每一次对话或任务切入时，强行让 AI 回归第一性原理，抵抗 LLM 本身的发散。

## 执行步骤

1. 阅读手册
   调用view_file工具完整阅读项目根目录下的 CLAUDE.md 文件中的开发工作流与绝对铁律章节。

2. 触发文风自检
   读完CLAUDE.md后，在脑海中划定一个单独的Task Boundary ，进行文风初始化断言：
   - [ ] 我将不再使用任何感叹号（!）和强烈的夸张形容词（如惊人的、极其的、极大可能等）。
   - [ ] 我将杜绝一切主观的推敲（如我猜、“也许因为），遇到异常直接提取真实数据做支撑。
   - [ ] 我所有的输出将采用纯净的中文，坚决杜绝解释性质的中英夹杂。

3. 闭环数据流程
   面对用户的具体任务，必须严格按序推进：
   - 基线：要求获取重构前的真实 CProfile 耗时或 NPS 数据作为参照点。若没有，请指出。
   - 防护网搭建：构思后，必须确认即将修改的代码不会引发跨模块错误。
   - 结果固化与核算：获取优化后的真实数据，计算净变动。最后将成果使用纯客观陈述写入相应的文档（如 `findings.md` 或 `progress.md`），并归档 Task 记录。
   - 测试拦截：功能重构完成后，必须完整运行被覆盖的 `pytest tests/`，直到 100% 绿灯，不允许开环提交。
   

4. 闭环任务流程
   当达到需要运行代码或脚本以观测事实与效果时，必须严格执行以下内容：
   - 提供必要的终端命令包裹于代码块中，请求用户自行运行，在用户反馈结果后，再进行后续分析。
   - 必须通过“闭环任务”与“闭环数据”两个环节落实成果：
     - 闭环任务：清晰界定起点与结束标准，绝不堆叠大量无收敛且未验证的文件变更。
     - 闭环数据：一切论断与验收必须附随测出数据（如 NPS 值、报错原文、或真实的运行耗时差）。坚决杜绝脱离实际、猜想性完工。
